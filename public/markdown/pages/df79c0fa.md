## 这张表适合怎么看

我没有把 `gemini评分` 当成唯一结论。租房这种事情很个人：有人更看重通勤，有人更看重隔音，有人宁愿贵一点也要省心。因此我更建议把它当成一个“候选池排序工具”。

几个字段可以组合起来看：

- `gemini评分`：Agent 根据通勤、租金线索、房屋质量、生活便利和风险信息给出的综合判断。
- `证据强度(0-10)`：公开资料是否足够丰富，不等于推荐度。证据强但评分低，往往意味着缺点也被搜得很清楚。
- `有效来源数`：被用于归纳的网页来源数量，方便判断结论是不是只来自单一页面。
- `租房价格线索`：从公开网页中抽取的月租、均价、户型价格等信息。
- `风险/差评线索`：噪音、老旧、停车、物业、疑似误命中等风险提醒。

我的使用方式通常是：先按评分和证据强度排序，排除明显不合适的；再搜索关键词，比如“隔音”“地铁”“老旧”“公寓”；最后点开来源做人肉复核。Agent 负责把信息压缩成第一轮筛选，人还是要为最终选择负责。

## 这个 Agent 做了什么

这次流程被我整理成了一个可复用的租房信息归纳 skill：[renting_research_skill.md](/data/renting_research_skill.md)。

它的核心思路是三段式：

1. 先用地图 API 找到公司和周边候选地点，解决“有哪些地方、离公司多远”的问题。
2. 再用公开网页搜索收集租金、户型、物业、隔音、配套、差评等线索，解决“住起来怎么样”的问题。
3. 最后让大模型把零散证据压缩成结构化字段，导出可以排序、筛选、追溯来源的 Excel。

这个 skill 的输入很少：公司名称、百度地图 AK、检索半径、目标 POI 类型、通勤方式、搜索服务和模型服务。输出则是一张适合直接决策的 Excel 表，字段包括名字、类型、地址、距离、通勤时间、证据强度、有效来源数、租房价格线索、房子质量线索、生活便利线索、风险线索、来源、AI 评分和 AI 总结。

## 为什么要做成 skill

租房调研有一个很强的复用性：换一家公司、换一个城市、换一个半径，本质工作流几乎不变。真正耗时间的是把这套流程稳定下来，比如：

- 同名小区要消歧，不能把别的城市或别的区域混进来。
- 地图 POI 要保留 uid、地址和坐标，否则后续路线和搜索都容易漂。
- 搜索结果要保留来源，AI 总结不能变成不可追溯的“玄学推荐”。
- 证据强度和推荐评分要分开，资料多不代表一定好住。

把这些规则写进 skill 后，Agent 下一次就不需要重新理解任务边界，可以直接按流程跑。它不是替我做决定，而是把原本几天的资料搜集压缩成一个可复核的数据底座。

## 一点反思

这张表并不等同于实时房源，也不能替代实地看房。网页信息会滞后，平台内容也会有噪声，部分价格线索可能来自二手房均价而不是租金。它更像一个“方向盘”：帮我快速知道哪些地方值得继续看，哪些地方要谨慎，哪些地方只是地图上离得近但公开口碑很弱。

我越来越觉得，Agent 最适合做这种“低创造性、高耐心、高交叉验证”的工作。它不需要一锤定音，只要能把混乱的信息变成一个能排序、能筛选、能追溯的表，人就已经轻松很多了。
